# AI 기획자가 되어보자 — 개발자를 위한 8회차 기획 스터디

> **비용 0원.** 책 안 삽니다. 전부 무료 자료(공식 블로그·공개 강의)로 진행합니다.
> **AI-Only.** 웹 검색·리서치 에이전트를 쓰지 않습니다. 모든 조사·작성·검증을 AI 대화만으로 진행합니다.

## 스터디의 목표와 진행 방식을 간략하게 소개해 주세요.

잘나가는 서비스를 **뜯어보고**(역기획) → 기획 문서를 **직접 써보고**(PRD·지표) → 내 아이디어를 **실제 사람에게 검증**하는 8회차 스터디입니다.

개발자로 일하다 보면 "이거 왜 만들어요?"라고 물었는데 아무도 답을 못 하는 순간이 옵니다. 열심히 만들었는데 아무도 안 쓰기도 하고요. 그 감각을 만드는 게 목표입니다.

**목표 3가지**

1. **기획자의 마음가짐** — 정보가 부족해도 결정하고, 틀렸을 때 책임지는 태도
2. **기획 기법** — PRD, 유저 인터뷰, 지표 설계, 우선순위를 실제로 쓸 줄 아는 것
3. **사업을 보는 눈** — 이 회사가 어떻게 돈을 벌고, 왜 성장했고, 어디가 위험한지 읽는 능력

### 진행 방식 — 3단 구조

기획 스터디는 대개 "책 읽고 → 요약 발표하고 → 아무것도 안 바뀜"으로 망합니다. 그래서 **매 회차 반드시 산출물을 만들어 옵니다.**

| 단계 | 회차 | 하는 일 | 요리로 치면 |
|---|---|---|---|
| 👀 **눈** | 1~3 | 역기획 — 남의 서비스를 뜯어본다 | 맛집 가서 먹어보고 레시피 추측하기 |
| ✋ **손** | 4~6 | 기법 — 내가 직접 기획 문서를 쓴다 | 레시피 직접 써보기 |
| 🧠 **머리** | 7~8 | 실전 — 내 아이디어를 검증한다 | 내 요리 만들어서 남한테 먹여보기 |

### 매 회차 2시간 진행

| 시간 | 내용 |
|---|---|
| 00:00~00:10 | 체크인 — 만들면서 막혔던 지점 공유 |
| 00:10~01:00 | 발표 (1인 10분) — 슬라이드 금지, 문서 그대로 화면공유 |
| 01:00~01:40 | **반박 타임** — 악마의 변호인 / CEO 역할이 공격 |
| 01:40~02:00 | 다음 회차 주제·역할 배정 |

> **왜 반박 타임이 40분이나 되나**
> 발표는 준비하면 누구나 합니다. 하지만 **내 기획안이 공격당했을 때 방어하는 경험**이 기획력을 만듭니다. 실무에서 기획자가 하는 일의 절반이 개발자·디자이너·대표가 "왜요?"라고 물을 때 답하는 일입니다.

### 🤖 AI-Only 방침

목표가 "AI 기획자가 되는 것"이니 **도구부터 AI-native로** 갑니다. 웹 검색과 리서치 에이전트를 쓰지 않고, **모든 조사·작성·검증을 AI 모델과의 대화만으로** 진행합니다.

다만 검색을 끄면 **AI가 매출·MAU 같은 숫자를 그럴듯하게 지어냅니다.** 그대로 두면 스터디 전체가 환각 위에서 토론하게 되므로, 규칙을 이렇게 바꿉니다.

| 기존 규칙 | AI-Only 규칙 |
|---|---|
| 숫자 3개 + **출처 필수** | 숫자 3개 + **신뢰도 등급 필수** |
| DART·뉴스에서 확인 | **다중 모델 교차검증**으로 확인 |

**신뢰도 등급** — 모든 사실 주장에 표기합니다.

| 등급 | 기준 | 사용 |
|---|---|---|
| **[A] 확신** | 여러 모델이 같은 답 + 상식과 부합 + 근거 설명 가능 | ✅ 논거 사용 가능 |
| **[B] 추정** | 방향은 일치하나 수치가 모델마다 흔들림 | △ "대략 이 규모" 수준만 |
| **[C] 환각 의심** | 모델마다 답이 다름 / 구체적인데 근거를 못 댐 | ❌ **논거 사용 금지** |

> **이게 손해처럼 보이지만 아닙니다.**
> "AI가 준 답을 어디까지 믿을 것인가"를 판정하는 훈련은 AI 프로덕트 기획자가 매일 하는 일 그 자체입니다. 8주 반복하면 그게 곧 **eval 설계 감각**이 됩니다.

**가장 중요한 AI 사용 규칙**: AI에게 **"대신 써줘"는 금지, "공격해줘"만 허용**합니다. PRD와 원페이저는 내가 먼저 쓰고, AI는 그걸 반박하는 심사위원 역할로만 씁니다. AI가 쓴 걸 다듬으면 기획 근육이 안 붙습니다.

## 목표를 달성하기 위해 각 회차마다 어떤 하위 주제를 공부할 예정인가요?

| 회차 | 단계 | 주제 | 다음 시간까지 만들어 올 것 |
|---|---|---|---|
| **1** | 👀 | OT + 기획이란 무엇인가 / "형용사 금지" 훈련 | 역기획 ① + **예측 봉인** |
| **2** | 👀 | 역기획 ① — 이 회사는 어떻게 돈을 버나 (BM) | 역기획 ② (승자/패자 비교) |
| **3** | 👀 | 역기획 ② — **예측 봉인 개봉** / AI 프로덕트 | PRD 1장 |
| **4** | ✋ | 문제 정의 + PRD / 인터뷰 질문지 제작 | **AI 페르소나 5명 + 실제 1명 인터뷰** |
| **5** | ✋ | 인터뷰 결과 — **AI vs 실제 비교** / 유도질문 잡아내기 | 지표 트리 + 우선순위(RICE) |
| **6** | ✋ | 지표 설계 + 우선순위 / 아이디어 브레인스토밍 | 원페이저 + **검증 착수** |
| **7** | 🧠 | 내 아이디어 세우기 — **전원 공격** | 검증 실행 + 계속/접기 결론 |
| **8** | 🧠 | 검증 결과 발표 + 8주 회고 | — |

> 🔓 **이 스터디의 핵심 장치 — 예측 봉인**
> 2회차에 "이 회사가 N년 시점이었다면 다음 수는?"을 **검색 없이** 예측해 봉인 제출하고, 3회차에 열어서 실제와 대조합니다.
> 잘된 회사를 보고 이유를 지어내는 **후행 합리화**를 원천 차단하고, **채점 가능한 훈련**으로 만들기 위해서입니다.

### 이 스터디의 규칙

| 규칙 | 왜 |
|---|---|
| **매 회차 산출물 필수** — 못 내면 발표 순서 없음 | 요약 발표 릴레이 방지 |
| **6회차까지 코드 금지** | 개발자 스터디 최대 함정. 참아야 기획 근육이 붙습니다 |
| **숫자 3개 + 신뢰도 등급 없으면 발표 불가** | 감상문 방지 (AI-Only라 출처 대신 등급) |
| **매 회차 1명은 "악마의 변호인"** | 발표를 무조건 깨려고 시도. 역할이니 감정 상하지 않습니다 |
| **역기획 회차엔 1명이 "그 회사 CEO"** | 개선안을 전부 방어. 방어하는 쪽이 더 배웁니다 |
| **완벽하게 만들지 말 것** | A4 1~2장. 못 채운 항목은 "모르겠음"이라고 쓰고 오면 됩니다 |
| **모든 사실 주장에 [A/B/C] 등급 표기** | 등급 없으면 발표 불가. [C]는 논거 사용 금지 |
| **AI에게 "대신 써줘" 금지 / "공격해줘"만 허용** | AI가 쓴 걸 다듬으면 기획 근육이 안 붙습니다 |
| **매 회차 "AI가 틀렸던 순간" 1개 공유** | 8주 쌓이면 AI 신뢰 한계선 지도가 됩니다 |

### ⚠️ 개선안 게이트

개선안을 내기 전에 반드시 이 절차를 통과해야 합니다.

1. 개선안을 쓴다
2. **"그 회사가 이걸 왜 안 했을까?" 이유를 3개 찾는다** (조직 / 법·규제 / 수익구조 충돌 / 기존 유저 반발 / 기술 부채 / 타이밍)
3. 3개를 못 찾으면 → 아직 이해 못 한 것. **제출 금지**
4. 3개를 찾고도 여전히 해야 한다면 → 그때 제안

5년간 수백 명이 고민한 제품에 2주 본 사람이 개선안을 내면 거의 항상 **"이미 해봤고 이유가 있어서 접은 것"**이 나옵니다. 이걸 반복하면 "왜 이거 안 하지?"라고 쉽게 말하는 나쁜 습관이 붙습니다.

## 🛠 개발자라서 할 수 있는 것

다른 기획 스터디는 못 하는 우리만의 무기입니다.

- **앱 릴리즈 노트 전체 히스토리 = 그 회사의 실제 로드맵** — 크롤링해서 타임라인화
- **네트워크 요청 분석** — 무엇을 수집하는가 = 무엇을 중요하게 보는가
- **A/B 테스트 흔적 / 피처 플래그** 탐지
- **API 구조 역추적** — 도메인 모델이 드러남 (야놀자 API를 보면 그들이 "숙소"를 어떻게 정의했는지 나옵니다)
- **앱 내 SDK 목록** — 어떤 분석툴·광고 인프라를 쓰는지

이 각도로 정리된 역기획 자료는 시중에 거의 없습니다. **블로그로 공개하면 그 자체가 포트폴리오**가 됩니다.

| 로드맵 추론 | BM에서 **논리적으로 연역** — 이게 오히려 더 좋은 훈련입니다 |

## ✅ 참여 전 확인

- [ ] 8주간 **주 2시간 모임 + 준비 2~3시간** 낼 수 있다
- [ ] 4회차 숙제로 **실제 사람 1명 이상을 인터뷰**할 각오가 있다 (나머지는 AI 페르소나로 대체)
- [ ] 6회차까지 **코드를 안 짜고** 버틸 수 있다
- [ ] 내 기획안이 **공개적으로 반박당하는 것**을 받아들일 수 있다
- [ ] **웹 검색 없이 AI만으로** 조사하는 방식에 동의한다

### 1회차 전에 할 일 (30분)

1. 디스코드 / GitHub 저장소 참여
2. **내가 매일 쓰는 앱 1개** 정하고 "이 기능은 왜 있을까?" 3개 적어오기 (한 줄씩이면 충분)

준비물은 이게 전부입니다. **책도, 돈도 필요 없습니다.**

| 기획자 마음가짐 | ❌ 남의 회사 평가는 **틀려도 손해가 0**이라 마음가짐이 생길 자리가 없습니다 |

그리고 **창업이 목표라면 분석 대상 자체가 달라져야 합니다.** 대기업 사례는 "1→100" 이야기인데, 창업 앞에서 필요한 건 "0→1"이거든요.

| 흔히 보게 되는 것 | 실제로 필요한 것 |
|---|---|
| 토스의 슈퍼앱 전략 | 토스가 **첫 1,000명**을 어떻게 모았나 |
| 당근의 지역 광고 BM | 당근이 **판교에서만** 시작한 이유 |
| 쿠팡의 물류 투자 | 쿠팡이 **처음 판 게 무엇이었나** (소셜커머스였습니다) |
| MAU 3,000만 | **첫 매출 100만원**이 언제, 어디서 났나 |

그래서 **역기획 3회 : 기법 3회 : 실전 2회**로 구성했습니다.
