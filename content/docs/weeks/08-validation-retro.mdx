## 왜 AI로만 만드나

1인 사업에는 디자이너도 리서처도 없습니다. 제안서가 필요하면 혼자 만들어야 하고, 그때 쓸 수 있는 건 AI뿐입니다.

이 제약은 인위적인 게 아니라 **앞으로의 기본값을 미리 겪어보는 것**입니다. 그리고 끝까지 맡겨봐야 AI가 어디까지 해주고 어디서부터 내 판단이 필요한지를 알게 됩니다.

<Callout type="warn">
**손으로 만든 장표는 한 장도 없어야 합니다.** 리서치, 구조 잡기, 슬라이드, 발표 스크립트까지 전부 AI로 만듭니다.
</Callout>

**써도 되는 것** — 어떤 AI 도구든 상관없습니다. 대화형 모델, 슬라이드 생성 도구, 이미지 생성, 리서치 도구 전부 허용입니다.

**하면 안 되는 것** — 직접 타이핑해서 문장을 고쳐 쓰거나, 도형을 손으로 그리거나, 예쁜 템플릿을 받아다 내용만 채우는 것. **프롬프트로 시키는 것까지가 내 일**입니다.

**단, 숫자는 예외입니다.** 7회차에서 직접 검증해 얻은 실제 숫자는 손으로 넣습니다. AI가 만들어낸 숫자를 발표에 올리면 그건 <Term>환각</Term>이고, 이 스터디에서 가장 하지 말아야 할 일입니다.

## 제안 PPT 구성

이 순서를 권합니다. 투자 제안이 아니라 **"이걸 왜 해야 하는가"를 설득하는 문서**입니다.

| 장 | 내용 | 어디서 나왔나 |
|---|---|---|
| 1 | 이 문제는 **누구의 것인가** | 4회차 문제 정의 |
| 2 | 지금 그 사람들은 **어떻게 버티고 있나** | 5회차 유저 인터뷰 |
| 3 | 우리는 **무엇을 다르게 하나** | 6회차 원페이저 |
| 4 | **실제로 해봤더니** — 검증 숫자 | 7회차 검증 |
| 5 | **어떻게 돈을 버나** | 2회차 <Term>BM</Term> 역기획에서 배운 틀 |
| 6 | 그래서 **다음에 무엇을 하겠다** | 오늘의 결론 |

8주 동안 만든 것이 그대로 6장이 됩니다. **새로 만드는 게 아니라 엮는 것**입니다.

## 2시간 타임테이블

### `00:00 ~ 00:05` 체크인

> "PPT 만들면서 AI한테 제일 답답했던 순간 하나만." — 한 사람당 한 문장.

### `00:05 ~ 01:00` 사업 제안 발표 (1인 11분)

**진행자는 발표 전에 그 사람이 7주차에 선언한 문장을 먼저 읽어줍니다.**

> "○○님은 지난주에 이렇게 말씀하셨습니다 — *'20명에게 보내서 3명이 이메일을 남기면 계속하겠다'*. 오늘 제안 들어보겠습니다."

**발표 (7분)** — 위의 6장 구성 그대로. 슬라이드를 띄우고 실제로 제안하듯 말합니다.

**질의 (4분)** — 듣는 사람은 **투자자나 동업자라고 생각하고** 묻습니다.

#### 🗡 결론 방어 질문

**결론이 "계속"인 경우** ← 여기를 더 세게 공격하세요
- 그 숫자, **7주차에 정한 기준을 진짜 넘겼나요?** 기준을 슬쩍 낮추신 건 아니고요?
- 반응한 사람들, **당신 지인 아닌가요?**
- "관심 있다"고 한 사람 중에 **돈을 내겠다고 한 사람은 몇 명**이죠?
- 이메일을 남긴 것과 **실제로 쓰는 것**은 다릅니다. 다음에 뭘로 확인하실 건가요?

**결론이 "접는다"인 경우**
- 접는 이유가 **결과 때문인가요, 본인이 지쳐서인가요?** (둘 다 유효하지만 구분은 해야 합니다)
- **문제가 없었던 건가요, 접근 방법이 틀렸던 건가요?** 이 둘은 완전히 다릅니다
- 다시 한다면 **어디부터** 다르게 하시겠어요?

**결론이 "애매하다"인 경우**
- 애매하다는 건 **강한 신호가 없다**는 뜻입니다. 그럼 접는 쪽 아닌가요?
- 뭘 더 보면 확실해지죠? 그거 **1주 더 하면 알 수 있나요?**

**슬라이드에 대해서도 한 번씩**
- 4장의 숫자, **직접 세신 건가요 AI가 채운 건가요?**
- 이 장표에서 **당신 판단이 들어간 곳**은 어디죠?

<Callout type="warn">
발표가 매끄러운 것과 제안이 설득되는 것은 다릅니다. AI가 만든 장표는 대체로 **매끄럽고 비어 있습니다.** 질의 시간은 그 빈 곳을 찾는 시간입니다.
</Callout>

> **진행자 강조 포인트**
> "접는다"고 결론 낸 사람에게 박수를 보내세요. **근거를 갖고 접는 판단**은 이 스터디에서 배울 수 있는 가장 비싼 기술입니다. 대부분의 창업 실패는 접어야 할 때 못 접어서 생깁니다.

### `01:00 ~ 01:10` AI는 어디까지 해줬나

준비해온 **프롬프트 기록**을 놓고 같이 봅니다. 이 10분이 이번 회차를 다음 8주로 잇는 자리입니다.

각자 한 문장씩 답합니다.

1. **AI가 제일 잘한 것** 하나
2. **끝까지 못 해준 것** 하나 — 그래서 결국 내가 판단해야 했던 지점
3. 다시 만든다면 **어떤 프롬프트부터** 다르게 쓰겠나

> 대부분 2번에서 같은 답이 나옵니다 — **"무엇을 뺄지"는 AI가 못 정해줬다.**
> 그게 기획입니다. 만드는 건 도구가 하고, **안 할 것을 정하는 건 사람이 합니다.**

### `01:10 ~ 01:40` 8주 회고

#### `01:10 ~ 01:22` 1주차의 나와 대조 ← 하이라이트

진행자가 **1주차에 각자 말한 "8주 뒤에 얻어가고 싶은 것"** 을 한 명씩 읽어줍니다.

각자 답합니다.
1. 그거 **얻었나요?**
2. 얻었다면 **어느 회차에서** 얻었나요?
3. 못 얻었다면 **뭐가 부족했나요?**

> 대부분 예상과 다른 답을 합니다. "기획 문서 쓰는 법 배우고 싶었는데, 실제로 남은 건 인터뷰였다" 같은. 그 차이를 확인하는 게 이 시간의 목적입니다.

#### `01:22 ~ 01:32` 회차별 회고

구글 문서에 같이 적습니다.

| 회차 | 가장 도움된 것 | 없어도 됐던 것 | 더 필요했던 것 |
|---|---|---|---|
| 1~3 (역기획) | | | |
| 4~6 (기법) | | | |
| 7~8 (실전) | | | |

**꼭 물어볼 것**
- **3주차 예측 대조**, 어땠나요? (이 장치가 효과가 있었는지 확인)
- **5주차 인터뷰**, 안 했으면 어땠을까요?
- **개선안 게이트** — 답답했나요, 도움됐나요?
- **AI만 쓰기 제약** — 배운 게 있었나요, 그냥 불편하기만 했나요?

#### `01:32 ~ 01:40` "1주차의 나에게 해줄 말"

한 사람당 한 문장. 준비해온 걸 읽습니다.

> 예시로 나오는 것들 —
> "남의 서비스 욕하기 전에 왜 그렇게 했는지부터 찾아라"
> "인터뷰를 무서워하지 마라. 3명만 만나면 세상이 달라 보인다"
> "안 할 것을 정하는 게 할 것을 정하는 것보다 어렵다"
> "코드부터 짜고 싶은 손을 참아라"

### `01:40 ~ 01:55` 이후 계획

**① 개인 — 각자 정하기**

| 선택지 | 내용 |
|---|---|
| **계속 간다** | 오늘 제안한 걸 이어서 검증 / 실제로 만들기 |
| **다시 판다** | 새 아이디어로 0→1 사이클 한 번 더 |
| **기록으로 남긴다** | 8주치 산출물 + 오늘 제안서를 **블로그/포트폴리오로 공개** ← 취업·이직 목표라면 이게 최선 |
| **쉰다** | 이것도 유효한 선택입니다 |

**② 스터디 — 시즌 2 논의**

| 방향 | 내용 |
|---|---|
| **A. 실행 시즌** | 오늘 제안 중 1~2개를 골라 **팀으로 실제 제작**. 이번엔 코드 허용 |
| **B. 심화 역기획** | 회차당 1개, 더 깊게. 개발자 무기(릴리즈 노트 크롤링, API 역추적) 본격 활용 |
| **C. AI 기획 심화** | eval 설계, 프롬프트 명세, AI 제품 원가 구조를 집중적으로 |
| **D. 여기서 종료** | 8주 완주 자체가 성과입니다. 억지로 이어가면 남는 게 없습니다 |

**③ 산출물 정리**

- [ ] 8주치 문서를 저장소에 정리 ([아카이브에 올리는 법](/archive#how-to-upload))
- [ ] 공개할 것 / 비공개할 것 분류
- [ ] 블로그 글로 낼 사람 정하기

### `01:55 ~ 02:00` 마무리

진행자가 한 마디로 닫습니다. 참고할 만한 정리 —

> 8주 동안 우리가 한 건 네 가지입니다.
> **남의 결정을 읽었고**, **내 문서를 썼고**, **내 판단을 시장에 던졌고**, 오늘 **그걸 사람들 앞에서 제안했습니다.**
>
> 마지막 게 제일 아팠을 겁니다. 근데 그게 기획자와 기획을 아는 사람의 차이예요.
> 기획을 아는 사람은 남의 결정을 잘 설명합니다. **기획자는 자기 결정을 책임집니다.**
>
> AI가 장표를 만들어줬지만, **무엇을 뺄지 정한 건 여러분입니다.** 그게 오늘 증명된 겁니다.
>
> 여러분은 이제 **"이거 왜 만들어요?"에 답할 수 있는 사람**입니다.

## 📌 스터디 종료 후 (선택)

### 산출물 정리 가이드

포트폴리오로 쓸 거라면 이 순서로 묶으면 좋습니다.

```
1. 역기획 3편        — 분석력 증명
2. PRD 1장           — 문서 작성 능력 증명
3. 인터뷰 기록       — ★ 이게 가장 희소합니다. 대부분 안 합니다
4. 지표 트리 + RICE  — 판단 근거 제시 능력
5. 검증 결과 + 결론  — ★ "접었습니다"로 끝나도 됩니다. 오히려 더 좋습니다
6. AI 제안서 + 프롬프트 기록 — ★ 과정까지 남긴 사람은 거의 없습니다
```

**면접에서 가장 잘 먹히는 건 3번, 5번, 6번입니다.**
- 3번: 실제로 사람을 만난 사람은 드뭅니다
- 5번: 근거를 갖고 접어본 사람은 더 드뭅니다
- 6번: "AI를 썼다"는 흔하지만, **어떻게 시켰는지를 남긴 기록**은 희소합니다

### 개발자라서 남길 수 있는 것

<Term>역기획</Term> 과정에서 만든 **릴리즈 노트 타임라인 / API 구조 분석 / SDK 목록**을 블로그로 공개하세요.
이 각도의 자료는 시중에 거의 없어서, 그 자체로 차별점이 됩니다.
